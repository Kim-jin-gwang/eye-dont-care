# **[WS] 랜덤 매칭 결과 수신**

| 항목 | 내용 |
| --- | --- |
| 진행상황 | 시작 전 |
| 통신 | WebSocket |
| 방향 | S→C |
| Connection | `/ws/match` |
| 구분 | 필수 |
| 역할 | 시스템→공통 |
| 사용할 페이지 | 로비/매칭 |
| 도메인 | Matchmaking |
| 설명 | RANDOM 대기방 생성 후 양쪽에 결과 전달. 이탈 후 자동 재매칭 결과도 이 소켓으로 수신 |

### **연결 정보**

---

| 항목 | 값 |
| --- | --- |
| Endpoint | /ws/match |
| 프로토콜 | WebSocket |
| 서버→클라 프레임 | 평면 구조 `{ "type": string, ...이벤트별 필드 }` (null 필드는 생략) |
| 이벤트 종류 | `MATCH_SUCCESS`, `MATCH_REQUEUED`, `MATCH_ERROR` |

### **Role Requirement**

---

**권한:** 매칭 대기 중인 사용자가 연결합니다.

### **연결 인증 (C→S, 첫 프레임)**

---

핸드셰이크는 익명으로 열린다. 브라우저는 WS 핸드셰이크에 헤더를 붙일 수 없으므로,
클라이언트가 연결 직후 **첫 프레임**으로 인증 정보를 보낸다. 서버가 토큰·세션을 검증하며
실패 시 연결을 닫는다. WS 흐름에서는 게스트 세션을 새로 발급하지 않는다.

- **회원**: `{ "type": "AUTH", "accessToken": "{JWT}" }`
- **게스트**: `{ "type": "AUTH", "guestSessionId": "{uuid}" }`

> 연결 순서: 게스트는 랜덤 매칭 신청(세션 발급) 후 응답의 `guestSessionId`로 연결한다.

### **매칭 성사 수신**

---

- **이벤트명**: `MATCH_SUCCESS`
- **설명**: 생성된 대기방으로 이동

```json
{
  "type": "MATCH_SUCCESS",
  "roomId": "019abcde-5678",
  "gameType": "EYEFIGHT"
}
```

### **자동 재매칭 재등록 수신 — `MATCH_REQUEUED`**

---

- **설명**: RANDOM 대기방에서 상대가 이탈해 방이 닫힌 뒤, 남은 참가자가 **현재 시각 기준으로 매칭 대기줄에 자동 재등록**되었음을 알린다. 클라이언트는 "다시 상대를 찾는 중" 상태로 전환하고 이 소켓을 유지한다. (`roomId` 없음)

```json
{
  "type": "MATCH_REQUEUED",
  "gameType": "EYEFIGHT"
}
```

### **자동 재매칭 오류 수신 — `MATCH_ERROR`**

---

- **설명**: 자동 재매칭 처리에 실패했음을 알린다. 클라이언트는 로비로 돌려보내거나 재시도를 안내한다.
- **code**: `MATCHMAKING-006`(재매칭 대상 무효 — 탈퇴/만료 등), `MATCHMAKING-007`(재매칭 처리 실패)

```json
{
  "type": "MATCH_ERROR",
  "code": "MATCHMAKING-006",
  "message": "자동 재매칭 대상이 유효하지 않습니다."
}
```

> 프레임은 평면 구조이며 값이 없는 필드(`roomId`/`code`/`message` 등)는 JSON에서 생략된다.
> 재매칭 흐름은 대기방(WaitingRoom) 이탈 감지에서 시작되어 이 소켓으로 결과가 전달된다.
