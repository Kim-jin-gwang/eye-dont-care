# 분석(analytics) 스키마 테이블 구조 — 참고·복붙용

dbt가 `analytics` 스키마에 생성하는 파생 테이블. 앱 ERD엔 넣지 않음(dbt가 CTAS로 재생성·관리).
아래 DDL은 **문서/복붙용** — 실제 생성은 `dbt run`이 `CREATE TABLE AS SELECT`로 함.

---

## 테이블 구조

### fact_game_play (분석 사실, 참가자 1행)
| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| participant_id | BIGINT | 참가자 ID (PK 성격) |
| result_id | BIGINT | 경기 결과 ID |
| game_name | VARCHAR(20) | 게임 |
| play_mode | VARCHAR(20) | SOLO/INVITE/RANDOM/AI |
| user_id | BIGINT | 회원 ID |
| slot_no | INT | 슬롯 |
| outcome | VARCHAR(20) | WIN/LOSE/DRAW/FORFEIT/COMPLETED |
| score | BIGINT | 서빙 컬럼 score |
| ended_at | TIMESTAMP | 종료 시각 |

### agg_user_game_stats (분석, 유저×게임 누적)
| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| user_id | BIGINT | 회원 ID |
| game_name | VARCHAR(20) | 게임 |
| play_count | BIGINT | 플레이 수 |
| win_count | BIGINT | 승리 수 |
| best_score | BIGINT | 최고 점수 |

### game_daily_stats (분석, 게임·모드·일자별)
| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| game_name | VARCHAR(20) | 게임 |
| play_mode | VARCHAR(20) | 모드 |
| play_date | DATE | 일자(KST) |
| play_count | BIGINT | 플레이 수 |
| player_count | BIGINT | 플레이어 수(distinct) |
| avg_score | NUMERIC | 평균 점수 |
| best_score | BIGINT | 최고 점수 |

### reconcile_score (감사, 불일치 리포트 — 정상이면 0행)
| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| participant_id | BIGINT | 참가자 ID |
| user_id | BIGINT | 회원 ID |
| slot_no | INT | 슬롯 |
| stored_score | BIGINT | 사본(participants_.score) |
| expected_score | BIGINT | 원본 기대값(game_result JSONB) |
| issue_type | VARCHAR(10) | MISSING / MISMATCH |

---

## 복붙용 DDL (참고)

```sql
CREATE SCHEMA IF NOT EXISTS analytics;

CREATE TABLE analytics.fact_game_play (
  participant_id BIGINT,
  result_id      BIGINT,
  game_name      VARCHAR(20),
  play_mode      VARCHAR(20),
  user_id        BIGINT,
  slot_no        INT,
  outcome        VARCHAR(20),
  score          BIGINT,
  ended_at       TIMESTAMP
);

CREATE TABLE analytics.agg_user_game_stats (
  user_id     BIGINT,
  game_name   VARCHAR(20),
  play_count  BIGINT,
  win_count   BIGINT,
  best_score  BIGINT
);

CREATE TABLE analytics.game_daily_stats (
  game_name     VARCHAR(20),
  play_mode     VARCHAR(20),
  play_date     DATE,
  play_count    BIGINT,
  player_count  BIGINT,
  avg_score     NUMERIC,
  best_score    BIGINT
);

CREATE TABLE analytics.reconcile_score (
  participant_id BIGINT,
  user_id        BIGINT,
  slot_no        INT,
  stored_score   BIGINT,
  expected_score BIGINT,
  issue_type     VARCHAR(10)  -- MISSING | MISMATCH
);
```

> 실제 컬럼 타입은 dbt CTAS가 소스에서 추론 — 위는 문서/복붙 편의용 표기.
> 원본 소스: fact/agg/daily는 `fact_game_play` 계보, reconcile는 `participants_` vs `game_result` JSONB 대조.
