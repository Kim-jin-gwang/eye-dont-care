# 랜덤 매칭 연동 — 쉬운 설명 버전

작성: 매칭/게임/게임결과 담당
(자세한 기술 버전은 `matchmaking-random-flow-전달.md` 참고)

---

## 한 줄 요약

랜덤 매칭이 성사되면 **대기방을 만들고 → 두 사람에게 알리고 → 게임 시작까지** 매끄럽게 이어지도록 매칭 쪽을 만들었고, `feat/backend`에 합쳤습니다. 테스트 515개 전부 통과.

---

## 1. 오늘 무엇을 했나

랜덤 매칭 전체 흐름을 이렇게 동작하게 만들었습니다.

1. 두 사람이 매칭되면 → **"이 둘 예약"** 이라고 잠시 묶어둠 (다른 요청이 끼어들지 못하게)
2. 대기방을 만들어달라고 요청 → 방 번호를 받음
3. **아직 같은 예약이 맞는지 확인** 후 확정 → 두 사람에게 "방 됐어!(MATCH_SUCCESS)" 알림
4. 두 사람이 대기방에 실제로 들어가면 → 매칭 상태 갱신
5. 게임 시작되면 → 매칭 기록은 임무 끝났으니 정리(삭제)

**실패하면?**
- 방 만들기 실패 → 예약 풀고, **아직 유효한 사람만** 다시 대기줄에 넣음(지금 시각 기준). 탈퇴했거나 만료된 사람은 정리.
- 방은 만들어졌는데 마무리에 실패(아주 드묾) → 그 방은 그냥 10분 뒤 자동으로 사라지게 두고, 사람만 다시 대기줄로. (팀 합의)

---

## 2. 대기방 담당자에게 전할 말

- 약속했던 연결 방식(RandomRoomCreator, lifecycle 신호)은 **그대로 지켰습니다.** 대기방 코드 바꿀 필요 없어요.
- **"방 만들었는데 마무리 실패 시 방 지우는 기능"은 안 만들기로 했어요.** 그냥 10분 뒤 자동 삭제(TTL)에 맡기기로 합의했으니, 대기방 쪽에 따로 만들 것 없습니다.
- 다만 **매칭↔대기방을 실제로 처음부터 끝까지 함께 돌려보는 테스트**는 아직 안 했어요. 이건 같이 한 번 확인해봐야 합니다.
- **다음 작업(재매칭)**: 랜덤 게임 시작 전에 한 명이 나가면 남은 사람을 자동으로 다시 매칭해주는 기능. 대기방 쪽은 이미 준비된 것 같으니, **"매칭이 뭘 해야 하는지" 정리해서 주시면** 이번처럼 붙이겠습니다.

---

## 3. 그 외 알아두면 좋은 것

### 배포 전에 꼭 (인프라/dev 담당)

- 운영(prod) 서버는 "허용할 주소(CORS)"를 설정값으로 받게 돼 있는데, **그 값이 아직 비어 있어요.** 이대로 운영에 올리면 **서버가 아예 안 켜집니다.** 배포 전에 값 하나 넣어줘야 해요.

### 프론트가 알아야 할 규칙

- **비회원(게스트)**: 게스트는 "방문증"을 따로 받는 곳이 없어요. **매칭 신청을 하면 그때 방문증(guestSessionId)이 응답에 담겨 옵니다.** 그걸 저장했다가 이후 요청엔 `X-Guest-Session-Id` 헤더에 넣어 보내야 해요. (순서: 매칭 신청 먼저 → 방문증 받기 → 이후 사용)
- **실시간 연결(WebSocket)**: 연결하자마자 **첫 메시지로 "나 누구야"를 보내야** 해요. 회원은 토큰, 게스트는 방문증 번호. 안 보내면 연결이 끊깁니다.
- **응답 모양**: 모든 응답이 `{ code, message, data }` 형태예요. 오류 코드는 `MATCHMAKING-002` 같은 식이고, 입력값 오류는 `data.fieldErrors`에 "어느 칸이 왜 틀렸는지" 들어옵니다.

### 아직 안 한 것 / 정해야 할 것

- **눈싸움 AI 모드 빼기**: 빼기로 했는데 아직 안 뺐어요. 지금은 게임 목록에 눈싸움 AI가 그대로 나옵니다.
- **게임 결과 저장용 gameId**: 매칭은 "게임 종류"만 다루는데, 결과 저장은 "게임+모드+난이도"로 된 정확한 id가 필요해요. 랜덤 게임이 끝난 뒤 이 id를 **누가 정할지 아직 안 정했어요.** 프론트/결과 담당과 얘기 필요.
- **ERD 그림**: 플레이 모드가 옛날(`MULTI`)로 그려져 있어요. 실제는 `INVITE/RANDOM`으로 나뉘었으니 그림 수정 필요.

## 정리

- 랜덤 매칭 연동은 **끝났고 합쳐졌습니다.**
- 대기방 담당: 바꿀 것 없음, 재매칭 다음 작업 문서만 주세요.
- 배포 전 CORS 값 넣기(필수), 프론트는 게스트/실시간 규칙 반영 필요.
