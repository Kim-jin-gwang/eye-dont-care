# 1차 QA 피드백 — 카테고리별 정리 (어디서 뭘 고칠까)

작성 기준: `main` (`1c4bf6c`). 정리 목적 = **담당 영역별로 나눠 액션 배분.**

## 담당 범례
| 표기 | 의미 |
|---|---|
| 🟦 FE | 프론트엔드 (Vue) |
| 🟥 BE | 백엔드 (Spring) — 🟢 내 담당(매칭/게임/게임결과/랭킹/소모임) · ⚪ 다른 분(auth·user) |
| 🎥 RTC | WebRTC/미디어(카메라) |
| 👁 AI | 아이트래킹(캘리브레이션·시선·깜빡임 인식) |
| 🎮 GAME | 게임 클라이언트 로직 |
| 🗄 PIPE | 데이터 파이프라인 |
| ⚙ 정책 | 팀 논의로 규칙부터 정해야 함 |

> 대부분 이슈는 **여러 영역이 걸침**(예: 404 토스트는 FE 표시 + BE 원인). "주 담당 / 함께" 로 표기.

---

## ★ 백엔드 "내 담당" 액션만 먼저 (우선순위)
1. **🟢 랜덤 매칭이 제대로 안 됨** — 매칭 성사/WS 이벤트 로직 점검 **(최우선)**
2. **🟢 방 코드 입장 검증** — 없는 코드 입력해도 새 방 생김 → 존재하지 않으면 에러로 입장 차단
3. **🟢 친구방 정원/중복 입장** — 2명 방에 3번째 들어오면 기존 상대가 빈 방에 남음 → 정원 초과 입장 거부(초과 시 세션 종료)
4. **🟢 게임결과 제출 404** — `POST /api/v1/game-results`는 존재함 → FE 호출경로·인증·바디 정합성 합동 점검("Vision API api 연동" = 이걸로 추정)
5. **🟢 경기 결과 시간 20초 고정** — 중간에 나가도 20초 기록 → 실제 경과시간으로 저장(클라가 20 보내는지/서버 고정인지 확인)
6. **🟢 최근 경기 기록 전부 1위** — mock 고정값인지 rankNo 계산 오류인지 구분
7. **🟢 랭킹 실제 응답 스펙 재확인·전달** — 프론트 mock 교체 지원
8. **🟢 소모임 검색 API 길이/성능 정책** 결정
9. **🟢/공통 실시간 상태(WebSocket)** — 매칭/상대/준비 상태 즉시 반영되게 이벤트 발행 점검
10. **공통 피드백 전송 API 부하 테스트** (담당 확인 필요)

> ⚪ 이메일 검증·프로필 저장 404·프로필 이미지 변경 오류 = **auth/user 담당** (내 도메인 아님)

## 🗄 데이터 파이프라인
- **직접적인 QA 버그 없음.** 랭킹이 실제 데이터로 뜨기 시작(=FE 연동 후)하면 집계·감사 파이프라인이 실제로 활용됨. 지금은 대기 상태(정상).
- "최근 경기 전부 1위"가 실제 순위 계산 오류로 판명되면, 야간 **reconcile 감사**로도 이런 데이터 이상을 잡을 수 있음(보조 안전망).

## ⚙ 정책/설계 결정 필요 (팀 논의 먼저)
1. 새로고침 시 게임 종료 여부
2. 카메라 종료/해제 시 게임 진행 정책
3. "다시 플레이" 동의 규칙(양측 동의)
4. 소모임 검색어 길이 상한(예: 50자)
5. **소모임 상세에 게시글/일정 넣을지** — 현재 백엔드 미구현 = **신규 스코프**(소개·참여자 명단은 이미 있음)

## 확인 필요(모호)
- **"Vision API api 연동 안 됨"** — 그림 제출 실패. 게임결과 제출(`/game-results`) 404와 같은 원인으로 추정. FE가 부르는 실제 URL 로그 확인 필요.
- **랜덤 매칭 관련 여러 증상**(안됨/대기 안 올라감/박스 안닫힘) — BE 매칭 성사 문제 + FE 대기 UI 문제가 섞여 있음. 재현 로그로 분리 필요.
