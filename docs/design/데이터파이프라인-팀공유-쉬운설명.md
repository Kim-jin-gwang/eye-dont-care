# 데이터 파이프라인 — 팀 공유용 쉬운 설명

작성: 데이터/백엔드 담당
대상: 파이프라인이 처음인 팀원 누구나

---

## 0. 한 줄 요약
게임 결과를 **① 실시간으로 화면에 보여주고(랭킹·전적)**, **② 밤마다 자동으로 검사·분석하는** 두 갈래 시스템을 만들었어요. 두 갈래는 **완전히 분리**돼 있어서, 밤 배치가 있어도 **랭킹은 항상 실시간**이에요.

---

## 1. 왜 만들었나
- 게임 점수가 지금까지 **JSON 덩어리(`game_result`)** 안에만 들어 있었어요. 랭킹처럼 **수많은 유저를 점수로 정렬**할 때 매번 이 JSON을 뜯어보는 건 느려요.
- 그래서 **점수만 별도 칸(`score` 컬럼)에 복사**해서 빠르게 정렬하게 하고, JSON 원본은 그대로 두었어요(상세·검사용).
- 그리고 **밤마다** 데이터가 잘 들어갔는지 검사(감사)하고 통계를 만드는 자동 배치를 붙였어요.

---

## 2. 큰 그림 (두 갈래)
```
게임 끝 → 제출 → [ 원본 JSON  +  score 칸 ] 둘 다 저장
                        │
   낮(실시간) ──────────┤── 랭킹·전적 화면 ← score 칸에서 바로 읽음 (빠름)
                        └── 게임 상세 화면 ← JSON에서 읽음
                        │
   밤(자동 배치) ───────→ 검사(사본 vs 원본 대조) + 통계 만들기
```
- **낮 = 실시간 서빙**: 유저가 보는 화면. 운영 DB에서 바로 읽어 항상 최신.
- **밤 = 배치**: 검사·통계. 유저 화면과 무관(서빙 아님). 그래서 **느려도 랭킹엔 영향 없음.**

---

## 3. 핵심 개념 5개 (비유로)
| 용어 | 쉽게 |
|---|---|
| **score 컬럼** | 자주 쓰는 점수를 **빠르게 꺼내려고 따로 만든 칸**. JSON 원본에서 복사해 옴 |
| **JSON 원본(game_result)** | 게임 상세 데이터 **원본 창고**. 점수 외 콤보·라운드 등 다 여기 있음(상세·검사용) |
| **dbt** | SQL로 표를 만들어주는 도구. **요리(계산)는 DB가 하고, dbt는 레시피·순서·검사를 관리**하는 주방 감독 |
| **감사(reconcile)** | 밤에 **"score 칸(사본) = JSON(원본)"이 맞는지 대조**. 틀리면 리포트. 성적표 검산 같은 것 |
| **Airflow** | **밤마다 자동으로 배치를 돌려주는 알람 시계**(스케줄러). 매일 새벽 3시에 실행 |

---

## 4. 팀별로 알아야 할 것 (제일 중요)

### 프론트
- 게임 결과 제출할 때 점수는 **`gameResult: { "슬롯": { "score": 숫자 } }`** 구조로 보내면 돼요(지금 그대로 유지).
- 눈싸움은 **초(정수)**, 깜빡이는 횟수, 리듬/그림은 점수, 에어하키는 골 수.
- 자세한 건 `랭킹-JSONB-front-전달.md` 참고.

### 백엔드 팀원
- `participants_`에 **`score` 컬럼이 생겼어요**(제출 시 자동 저장). 랭킹·전적은 이 컬럼을 읽어요.
- **JSON 원본은 그대로** 있어요(상세·검사용). 없어진 데이터 없음.
- 서빙은 **실시간**이에요. 밤 배치와 무관.

### 전체
- **밤 배치(Airflow/dbt)는 유저 화면에 안 쓰여요.** 검사(감사) + 통계(분석)만. 그러니 배치가 느리거나 꺼져도 **랭킹·전적은 멀쩡**.

## 한 줄 정리
**"낮엔 빠른 칸(score)으로 실시간 서빙, 밤엔 자동으로 데이터 검사·통계"** — 두 갈래가 분리돼 있어서 서빙은 항상 실시간이고, 밤 배치는 데이터 신뢰성과 분석을 담당해요.
